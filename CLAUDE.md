# BluetoothBatteryWatch

A macOS 14+ menu bar app (SwiftUI `MenuBarExtra`, `LSUIElement`, no Dock icon) that shows the battery level of connected Bluetooth accessories. It sends a notification when one drops below a configurable threshold (default 50%). It's distributed as a signed, notarized cask through the Homebrew tap `bombadiltom/homebrew-tap`.

## Layout

- `BluetoothBatteryWatch/BatteryReader.swift` reads levels from the IORegistry: every service that has a `BatteryPercent` property, the same data as `ioreg -r -k BatteryPercent`. Devices are de-duplicated by Bluetooth address. Names come from `IOBluetoothDevice(addressString:)`. The `Product` key is often empty for Apple accessories, so don't rely on it.
- `BluetoothBatteryWatch/BatteryMonitor.swift` is the `@MainActor @Observable` state. It checks every 5 minutes, on wake and when the menu opens. It sends notifications and handles launch at login (`SMAppService.mainApp`). There is one alert per device per discharge cycle: the device's address goes into the `alertedDevices` set in `UserDefaults`, and it's removed once the level is back at or above the threshold.
- `BluetoothBatteryWatch/MenuContentView.swift` is the menu window. `BluetoothBatteryWatchApp.swift` sets up the app and the menu bar icon.
- `scripts/make-icon.swift` renders `Assets.xcassets/AppIcon.appiconset`. Edit the script and run it again (`swift scripts/make-icon.swift`); don't edit the PNGs by hand.
- `scripts/release.sh`, `scripts/setup-ci-secrets.sh` and `.github/workflows/release.yml` handle releases. See below.

## Build

The project is generated by XcodeGen from `project.yml`. Run `xcodegen generate` after adding, removing or moving files, or after changing `project.yml`. `Info.plist` is generated too, so change its keys under `info.properties` in `project.yml`, not in the plist.

```bash
xcodegen generate
xcodebuild -project BluetoothBatteryWatch.xcodeproj -scheme BluetoothBatteryWatch -configuration Release -derivedDataPath build build
```

Local builds are signed ad hoc (`CODE_SIGN_IDENTITY: "-"`). There's no test target.

## Releasing

- Normal release: `scripts/release.sh <version>`. It requires a clean tree with HEAD already pushed. It tags `v<version>` and pushes the tag. The **Release** action then builds, signs with the Developer ID, notarizes, staples, publishes the GitHub release and rewrites `Casks/bluetoothbatterywatch.rb` in the tap through a deploy key.
- `--build-only` builds and notarizes into `dist/` without publishing. Running the action manually from the Actions tab does the same.
- `--publish-existing-tag` is what the action runs. It's also the local fallback when the action is unavailable.
- The cask file in the tap is generated by `release.sh`. Change the cask template there, not in the tap repo.
- Versions: `MARKETING_VERSION` is the release version and `CURRENT_PROJECT_VERSION` is `git rev-list --count HEAD`, both passed to `xcodebuild`. `Info.plist` must keep `$(MARKETING_VERSION)` and `$(CURRENT_PROJECT_VERSION)`. A literal value there once made v1.1 report 1.0.
- Signing: team `K6QN2C7Q55` (individual account, "Tom Lorenz"), identity `Developer ID Application: Tom Lorenz (K6QN2C7Q55)`, and the notarytool keychain profile `BombadilTom`. The action rebuilds all of this from the repo secrets listed at the top of `release.yml`.
- Notarization needs `CODE_SIGN_INJECT_BASE_ENTITLEMENTS=NO`, `--timestamp` and the hardened runtime. Without the first, Xcode adds `get-task-allow` and Apple rejects the build.
- Mac App Store: `--app-store-build-only` exports a signed `.pkg` into `dist/`, and `--app-store` also uploads it with an App Store Connect API key (`ASC_KEY_ID`, `ASC_ISSUER_ID`, `.p8` in `~/.appstoreconnect/private_keys/`). This is a separate sandboxed build: `BluetoothBatteryWatch/AppStore.entitlements` (sandbox + Bluetooth) is only passed in these modes, together with the "Apple Distribution" / "3rd Party Mac Developer Installer" certificates and the provisioning profile `BluetoothBatteryWatch App Store`. The Homebrew build stays unsandboxed. The sandbox was tested in Nov 2026: IORegistry reads and IOBluetooth names both work. Its settings live in the container, so `importLegacySettings()` finds nothing there. `PRIVACY.md` is the App Store privacy policy URL. The App Store upload isn't in the GitHub Action, so it's run locally.
- Never handle the certificate, `.p12`, Apple ID password, App Store Connect `.p8` key or deploy key yourself. Setting those up is the user's job, through `scripts/setup-ci-secrets.sh` and `xcrun notarytool store-credentials`.

## Things to know

- **Bundle ID:** it's `de.idiotentruppe.batterywatch`. The `batterywatch` suffix is left from the app's first name, BatteryWatch. Before 1.2 the ID was `de.lorenz-unna.batterywatch`.
  - Don't change it casually. A new ID resets notification permission and the login item for existing installs.
  - `BatteryMonitor.importLegacySettings()` copies the threshold and alert state once from the old ID's defaults, using the `legacyDomains` list. If the ID ever changes again, add the current one to that list.
  - The cask's `zap` removes the preference files of both IDs.
- **GitHub account:** the repo and the tap belong to `bombadiltom`, but the active `gh` account on this Mac is `tlorenz-reply`, so don't switch it. Use `GH_TOKEN=$(gh auth token --user bombadiltom) gh …`. `release.sh` already does that. Git pushes go over SSH (`git@github.com:bombadiltom/…`).
- **Git identity:** the personal identity only applies inside `~/Projects/private/` (`includeIf` in the global git config). Git operations outside it, such as a clone in `/tmp` or Homebrew's copy of the tap, commit under the work identity. That's why `release.sh` clones the tap into `build/`.
- **Homebrew 7** refuses casks from untrusted taps, so the install instructions need `brew trust --cask bombadiltom/tap/bluetoothbatterywatch`. `brew style` wants `depends_on macos: :sonoma`, not `">= :sonoma"`.
- **Login item:** to check it after reinstalling or moving the app, run `sfltool dumpbtm | grep -B1 -A1 "2.de.idiotentruppe.batterywatch"`. It should show `enabled` with the `/Applications` path.
- **`release.sh` runs on macOS's bash 3.2.** Under `set -u`, expanding an empty array fails, so use the `${arr[@]+"${arr[@]}"}` form.
